# «Травница», план 5: новый дизайн «полевой дневник» — дизайн

Дата: 2026-10-18
Основа: спецификация `2026-10-15-travy-design.md` (§6 экраны, §9 стиль). Этот документ заменяет §9 и меняет вид карточки травы из §6.2.3; логика фильтров, поиска, избранного, обновлений — без изменений.
Референс: макеты пользователя в `docs/design/travnitsa/` (01-icon, 02-home, 03-herb-card, 04-catalog, 05-recipes, 06-favorites).

## 1. Зачем

Пользователь прислал макеты в стиле «полевого дневника»: кремовая бумага, карточки с рваными краями, акварельные ботанические рисунки, засечный шрифт, рукописные заметки. Это стиль будущего продукта «Травница» (сообщество + дневник), к которому приложение потом вырастет. Сейчас — перевести существующий справочник в этот стиль и разгрузить карточку травы: в ней сейчас всё одной длинной лентой, а нужно — только основное, остальное по кнопке.

## 2. Решения пользователя

| Вопрос | Решение |
|---|---|
| Стиль | Как на макетах `docs/design/travnitsa/`: светлая «бумажная» тема; тёмная тема убирается |
| Название | «Травница» (пока) — вместо «Травы» |
| Иконка | Как `01-icon.webp`: веточка шалфея на кремовой бумаге |
| Карточка травы | Сразу видно: действующие вещества, применение, от чего помогает с уровнем доказанности — «примерно как на скрине» `03-herb-card.webp`; остальное — по отдельной кнопке |
| Картинки трав | Ботанические рисунки из старых атласов в общественном достоянии (Köhler's Medizinal-Pflanzen 1887 и подобные); фото уходят в «Подробнее» |

## 3. Цели, не-цели, анти-цели

**Цели**
- Новая тема: палитра, бумажная текстура, рваные края карточек, шрифты, тонкие контурные иконки — на всех экранах.
- Карточка травы по макету 03 + экран «Подробнее о траве» со всем остальным.
- Ботанический рисунок у каждой из 6 трав: в карточке, в списках, на главной.
- Новое название и иконка.

**Не-цели**
- Дневник, профиль, лента, аккаунты (это «Травница»-сообщество, позже).
- Вкладки с макетов «Открытия», «Дневник», «Профиль», «Травник»; сегменты «Мои / Рекомендуемые» в сборах, «Травы / Сборы / Свойства» в избранном.
- Онбординг.
- Новые травы и правка медицинского содержания.
- Тёмная тема (возможна позже — тема остаётся в одном модуле `theme/`).

**Анти-цели**
- Красиво, но нечитаемо: мелкий бледный текст, рукописный шрифт для чего-либо, кроме заметок и украшений.
- Сломанные обновления базы: установленный APK 1.0.0 (схема 1) должен принимать базы, опубликованные после этого плана, — новые поля только необязательные, перечисления не меняются, `SCHEMA_VERSION` остаётся 1.
- Потеря возможностей: всё, что сейчас есть в карточке (источники, уровни, «с чем спутать», безопасность, фото с авторством, заметка, кликабельные метки), остаётся доступным — сразу или в «Подробнее».
- Нарушение лицензий: у каждого рисунка и картины — автор/источник/лицензия в «О приложении», как у фото.

## 4. Как устроено

### 4.1. Тема (`app/src/theme/`)

- Палитра (из описания «Травницы» пользователя): фон `#F5F0E8`, карточки `#EDE6DB`, текст `#3A3226`, вторичный текст `#5A4A3A`, акцент шалфей `#8A9A7B`, акцент мох `#5B6F4E`, разделители `#C8BFAF`. Цвета уровней доказанности остаются смысловыми (зелёный / жёлтый / оранжевый / красный), но подбираются под светлый фон с контрастом текста ≥ 4.5:1 там, где на них есть текст.
- Шрифты (Google Fonts через `@expo-google-fonts/*`, загрузка при старте, сплэш держится до загрузки): заголовки — Cormorant Garamond; основной текст — читаемый шрифт с засечками и кириллицей (выбор исполнителя: Lora или PT Serif); рукописный — Caveat, только для заметки пользователя и мелких украшений.
- Бумага: лёгкая текстура фона (сгенерированная PNG-плитка, коммитится) — не мешает чтению.
- Рваные края: компонент «бумажная карточка» рисует неровный край SVG-путём (`react-native-svg`), край детерминированный (зависит от размера/ключа, не «прыгает» при перерисовке), с мягкой тенью. Плашки-метки — тоже с лёгкой неровностью или скруглённые, как на макетах.
- Иконки: тонкие контурные (исполнитель выбирает набор; допускается `phosphor-react-native` с весом `light` или текущий MaterialCommunityIcons-outline).
- `userInterfaceStyle: light`, статус-бар тёмный.

### 4.2. Картинки

- **Ботанический рисунок** — новое *необязательное* поле травы `illustration` (та же структура, что у фото: `file`, `caption?`; автор/лицензия/ссылка — в `photos.yaml`, как у фото). Старое приложение (схема 1, нестрогая схема) его просто игнорирует. Если рисунка нет — показывается первое фото, как сейчас.
- Источник: таблицы старых атласов на Wikimedia Commons в общественном достоянии (Köhler's Medizinal-Pflanzen 1887; если нужной травы там нет — Thomé «Flora von Deutschland» 1885 и т. п.). Берётся существующим `photo:fetch` (Wikimedia API → автор/лицензия), лицензия `PD`.
- Обработка: рисунок должен сливаться с кремовым фоном — фон старой бумаги осветляется/делается прозрачным при подготовке (в `tools`), подписи и номера таблицы по возможности обрезаются; WebP, длинная сторона ≤ 1080, прозрачность сохраняется.
- **Фото** остаются как есть и показываются в «Подробнее» (галерея с авторством).
- **Баннер на главной**: пейзажная картина в общественном достоянии (русская живопись XIX века — Шишкин, Левитан, Васильев и т. п.: лес, река, туман — как на макете 02), встроена в приложение, авторство в «О приложении». Не часть базы трав.
- **Иконка**: веточка шалфея из `docs/design/travnitsa/01-icon.webp` (картинка пользователя), без надписи, на кремовом фоне; адаптивная иконка Android, монохромная, сплэш, favicon — генерируются из неё скриптом `app:icons` (заменить рисование листа на вырезку из этой картинки). Оригинала крупнее нет: веточка ≈520 px, поэтому — вырезка + отделение от фона бумаги + увеличение (Lanczos) до нужных размеров; небольшая мягкость допустима *(решение Claude)*.

### 4.3. Карточка травы (по макету 03)

Сверху вниз:
1. Шапка: «назад», «сердце» (избранное).
2. Название (Cormorant), латынь; справа — ботанический рисунок (крупно, без рамки, на бумаге).
3. 2–3 плашки «от чего помогает» — **системы органов** травы (короткие названия из `organ-systems.yaml`: «Пищеварение», «Кожа и раны», «Простуда и иммунитет»…), нажатие → список трав с фильтром по системе органов *(решение Claude: названия показаний — длинные фразы, а почти все показания одного уровня `traditional`, поэтому «по уровню» не выбирает 2–3; системы органов — короткие, как на макете, и фильтр по ним уже есть)*. Порядок: больше показаний травы в системе → выше; при равенстве — лучший уровень доказанности среди её показаний; затем по названию.
4. Короткое описание (`description`).
5. Три бумажные карточки в ряд (на узком экране допускается горизонтальная прокрутка или перенос): **Части растения** (из `harvest[].part`, без повторов), **Действующие вещества** (названия из словаря), **Применение** («Внутрь: …» / «Наружно: …» по формам применения).
6. **От чего помогает** — все показания: название + точка уровня доказанности (+ подпись уровня), отсортированы по уровню; нажатие → список трав.
7. Печать: «проверено» при `status: checked`, «черновик» при `draft` (сейчас это плашка «Черновик — не проверено»).
8. «Моя заметка» — заметка пользователя рукописным шрифтом; нажатие — редактирование (существующий `NoteEditor`, автосохранение). Пустая — приглашение «Добавить заметку».
9. Кнопки: «Добавить в избранное / В избранном» и **«Подробнее о траве»**.

Деление форм применения *(решение Claude)*: внутрь — `infusion`, `decoction`, `tincture`, `tea`; наружно — `rinse`, `bath`, `compress`; `other` — не попадает в краткую строку (видно в «Подробнее»).

### 4.4. «Подробнее о траве» (новый экран `herb/[id]/details`)

Всё, что сейчас есть в карточке и не вошло в краткую: галерея фото с авторством и лицензией; другие названия; семейство, жизненная форма, где взять, где растёт (кликабельные метки); показания с пояснениями, уровнями и раскрываемыми источниками; применение полностью (рецепт, дозировка, курс, источники); сбор по месяцам и частям; действие; безопасность (беременность, кормление, дети, токсичность, противопоказания, предупреждения, побочные эффекты, взаимодействия); с чем можно спутать (ядовитые — выделены); список источников. Оформление — те же бумажные секции.

### 4.5. Остальные экраны

- **Главная** (макет 02): заголовок «Травница», поиск, 4 плитки (Каталог · Все травы · Избранное · О приложении) — бумажные, с контурными иконками; баннер-картина «Природа — лучшая аптека»; «Собирать сейчас · <месяц>» — бумажные карточки с рисунком, названием и 1–2 плашками.
- **Каталог / список трав / поиск** (макет 04): строки-карточки: рисунок слева, название, латынь, 1 строка, до 3 плашек. Фильтры и логика — без изменений, только вид. *(Решение Claude, по макету 04 — «Успокаивает, снимает воспаление…» / «Цветы · Успокоительное · Пищеварение»):* строка — действия травы из словаря `actions` через запятую со строчной буквы после первого («Противовоспалительное, спазмолитическое, ветрогонное»; нет действий — 2 первых показания); плашки — первая часть растения (без уточнения в скобках: «Трава (надземная часть)» → «Трава») + до 2 систем органов (как в карточке). Если в списке выбран фильтр по показаниям — вместо строки, как сейчас, выбранные показания с точкой уровня. Отметка «★ в избранном» заменяется контурным «сердцем» справа.
- **Сборы** (макет 05): карточки сборов: рисунки компонентов (до 2), название, состав одной строкой, плашки назначения. Сейчас сборов 0 — пустое состояние в том же стиле.
- **Избранное** (макет 06): как каталог + «сердце» и, если есть заметка, «штамп» с её началом рукописным шрифтом.
- **Карточка сбора, «О приложении», фильтры, дисклеймер, всплывающая плашка** — в новой теме без изменения состава.
- Нижние вкладки: Главная · Каталог · Сборы · Избранное (как сейчас), контурные иконки, активная — мох.

### 4.6. Название

`app.json`: `name` = «Травница»; `slug`, `scheme`, `android.package`, адрес базы, ключ хранилища — **без изменений** (иначе новая версия не встанет поверх старой и потеряет данные). Версия приложения → `1.1.0`, `versionCode` → 2.

## 5. Что остаётся на усмотрение исполнителя

- Конкретные таблицы атласов и картина для баннера (в рамках общественного достояния и подходящего вида).
- Шрифт основного текста (Lora или PT Serif), набор иконок.
- Алгоритм рваного края и текстуры, размер теней.
- Раскладка трёх карточек на узких экранах.
- Как именно убирается фон старой бумаги на рисунках.

## 6. Проверка

- Все существующие тесты проходят; новая логика без UI (краткое применение «внутрь/наружно», выбор 2–3 главных показаний, уникальные части растения) — в `shared` с тестами.
- Охранный тест совместимости не меняется (перечисления те же, `SCHEMA_VERSION` = 1); тест, что база с полем `illustration` проходит нестрогую схему версии 1 без него и с ним.
- Визуально — веб-превью 375×812 по всем экранам; затем APK 1.1.0 на телефоне пользователя.
- **Критерий готовности от пользователя: «делай до тех пор, пока в точности не будет похоже на референсы».** После реализации — циклы «скриншот экрана рядом с макетом → список расхождений → правка», пока расхождения не сведутся к тому, что невозможно без новых рисунков (рукописные иконки и акварель макетов — сгенерированные картинки; у нас — старые литографии и контурные иконки, это ограничение честно называется пользователю).
