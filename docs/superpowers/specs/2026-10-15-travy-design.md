# «Травы» — справочник лекарственных растений: спецификация

Дата: 2026-10-15
Статус: утверждена; дополнение 2026-10-15 (план 2): поля `life_form`, `sourcing`, страница проверки контента

## 1. Цель

Мобильный справочник лекарственных трав для себя и близких. Главная ценность — возможность группировать и сравнивать травы по любым общим признакам (от чего помогают, действующие вещества, действие, сбор, ботаника, безопасность) и честно видеть, насколько доказано каждое заявленное действие и откуда взята информация.

Приложение не публикуется в магазинах. Распространение — APK-файлом.

## 2. Решения, принятые на обсуждении

| Вопрос | Решение |
|---|---|
| Аудитория | Для себя и близких, без публикации в Google Play |
| Источник контента | Стартовую базу составляет Claude, пользователь проверяет; позже — дополнение по книгам пользователя |
| Источники | Обязательны; привязаны к каждому показанию; только достоверные и проверяемые |
| Доказанность | 4 уровня, у каждого показания свой |
| Группировки | Показания, действующие вещества (и их классы), действие, система органов, месяц сбора, часть растения, место произрастания, семейство, безопасность |
| Навигация | Каталог группировок + кликабельные метки в карточке + комбинированный фильтр + поиск |
| Фото | Несколько на траву, с Wikimedia Commons, встроены в приложение, работают офлайн |
| Доп. функции v1 | «С чем можно спутать», избранное и заметки, сборы и рецепты |
| Обновление базы | Приложение скачивает новую версию базы из интернета (GitHub Pages) |
| Платформы | Android сейчас; возможно iPhone позже |
| Технология | React Native + Expo, TypeScript |
| Визуальный стиль | «Природный, здоровый, гармоничный»; финально — по референсам пользователя |

### Предположения (пользователь может поправить)

- Язык интерфейса и контента — только русский.
- Травы — распространённые в средней полосе России и/или продающиеся в аптеках.
- Избранное и заметки хранятся только на телефоне, без синхронизации между устройствами.

## 3. Объём

### Входит в v1

- Справочник трав: карточка, каталог группировок, фильтр, поиск.
- Показания с уровнем доказанности и источниками.
- Сбор, применение, безопасность, «С чем можно спутать».
- Сборы (смеси трав).
- Избранное и личные заметки.
- Встроенная база + фоновое обновление базы с GitHub Pages.
- Экран настроек: версия базы, проверка обновлений, дисклеймер, авторы фото.
- Стартовый контент: пилот 10 трав → после одобрения 40–50 трав.

### Не входит в v1

- Сборка и установка на iPhone (кодовая база должна это позволять, но не собираем).
- Веб-версия (кодовая база должна это позволять — см. §4.3, `ContentStore`, но не публикуем).
- Синхронизация заметок между устройствами, аккаунты.
- Добавление трав и своих фото из приложения.
- Календарь сбора с напоминаниями.
- Определение растения по фото.
- Другие языки.

## 4. Архитектура

### 4.1. Репозиторий

Один публичный репозиторий на GitHub (npm workspaces):

```
travy/
├── content/                 исходные данные (YAML), правит человек
│   ├── herbs/<herb-id>.yaml
│   ├── recipes/<recipe-id>.yaml
│   ├── sources.yaml
│   ├── dictionaries/
│   │   ├── indications.yaml
│   │   ├── organ-systems.yaml
│   │   ├── substances.yaml
│   │   ├── substance-classes.yaml
│   │   ├── actions.yaml
│   │   ├── plant-parts.yaml
│   │   ├── habitats.yaml
│   │   └── families.yaml
│   └── photos/<herb-id>/<file>.webp  (+ photos.yaml с авторством)
├── shared/                  общий код: zod-схемы данных, типы, версия формата
├── tools/                   сборщик/валидатор, загрузчик фото с Wikimedia, проверка DOI/PMID
├── app/                     приложение Expo
└── .github/workflows/       CI: валидация, сборка и публикация базы на GitHub Pages
```

`shared/` используется и сборщиком (валидация исходников), и приложением (валидация скачанной базы) — одна схема, без расхождений.

### 4.2. Поток данных

```
content/*.yaml ──► tools/build ──► dist/
                    │ проверка схемы        ├── manifest.json
                    │ проверка ссылок       ├── content.json
                    │ правила источников    └── photos/<sha256>.webp
                    │ сжатие фото
                    ▼
            git push → GitHub Actions → GitHub Pages
                                         https://<user>.github.io/travy/
                                                   │
                         при сборке APK            │ раз в сутки, если есть сеть
                         dist/ копируется ──► app ◄┘
                         внутрь приложения
```

### 4.3. Приложение

- **Expo (актуальная стабильная SDK на момент старта), TypeScript, Expo Router** для навигации.
- **Контент в памяти.** `content.json` загружается целиком при старте; индексы для фильтров и поиска строятся в памяти. СУБД не используется (объём — единицы мегабайт даже на 300 трав).
- **Хранилище контента** — интерфейс `ContentStore` (читать активную базу, сохранить новую, найти фото). Реализация v1 — `expo-file-system`. Интерфейс нужен, чтобы будущая веб-версия подставила свою реализацию.
- **Встроенная база.** При сборке APK `tools` копирует `dist/` в ресурсы приложения и генерирует `bundled-photos.ts` — таблицу «путь фото → `require()`» (в React Native ресурсы подключаются только статически).
- **Фото** показываются через `expo-image`. Поиск файла: сначала скачанные (по sha256), затем встроенные, иначе — заглушка.
- **Пользовательские данные** (избранное, заметки) — `AsyncStorage`, ключ — `id` травы. Хранятся отдельно от контента и переживают обновления базы.
- **Тема.** Все цвета, шрифты, отступы, скругления — в одном модуле `theme/` (светлая и тёмная версии, по системной настройке). Экраны используют только токены темы. Смена визуального стиля = правка `theme/` без переписывания экранов.

## 5. Модель данных

Идентификаторы (`id`) — латиница-kebab-case, стабильные навсегда (для трав — от латинского названия: `matricaria-chamomilla`). Переименование `id` запрещено, т.к. к нему привязаны заметки пользователя.

### 5.1. Трава (`content/herbs/<id>.yaml`)

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `id` | string | да | Совпадает с именем файла |
| `name` | string | да | Русское название |
| `other_names` | string[] | нет | Народные и синонимичные названия (участвуют в поиске) |
| `latin` | string | да | Латинское название с автором |
| `family` | ref → families | да | Семейство |
| `status` | `draft` \| `checked` | да | `checked` ставит только пользователь |
| `life_form` | `herb` \| `subshrub` \| `shrub` \| `tree` \| `vine` | да | Жизненная форма: трава, полукустарник, кустарник, дерево, лиана |
| `sourcing` | (`wild` \| `garden` \| `pharmacy`)[] | да, ≥1 | Где взять: дикорастущее, садовое (культивируется), аптечное сырьё |
| `photos` | Photo[] | да, ≥1 | См. 5.5 |
| `description` | string | да | Внешний вид, как узнать |
| `habitats` | ref[] → habitats | да | Где растёт |
| `harvest` | Harvest[] | да, ≥1 | Сбор по частям растения |
| `substances` | ref[] → substances | да | Действующие вещества |
| `actions` | ref[] → actions | да | Фармакологическое действие |
| `indications` | Indication[] | да, ≥1 | Показания с доказанностью |
| `usage` | Usage[] | да, ≥1 | Способы применения |
| `safety` | Safety | да | Безопасность |
| `lookalikes` | Lookalike[] | нет | С чем можно спутать |
| `sources` | SourceRef[] | нет | Общие источники карточки (описание, ботаника) |

**Harvest:** `part` (ref → plant-parts), `months` (int 1–12, ≥1), `how`, `drying`, `storage` (строки), `sources` (SourceRef[], ≥1).

**Indication:**
- `indication` — ref → indications
- `evidence.level` — `proven` | `traditional` | `folk` | `refuted`
- `evidence.note` — строка, обязательна: кратко, на чём основан уровень («монография EMA, традиционное применение», «2 небольших РКИ, эффект умеренный»)
- `sources` — SourceRef[], ≥1

**Usage:** `form` (`infusion` настой | `decoction` отвар | `tincture` настойка | `rinse` полоскание | `bath` ванна | `compress` компресс | `tea` чай | `other`), `recipe`, `dosage`, `course` (необяз.), `for_indications` (ref[] → indications, необяз.), `sources` (≥1).

**Safety:**
- `pregnancy`, `lactation` — `ok` | `caution` | `contraindicated` | `unknown`
- `children` — `{ status: ok | caution | contraindicated | unknown, from_age?: int }`
- `toxicity` — `none` | `low` | `moderate` | `high`
- `contraindications` (EMA 4.3 и прямые «избегать»), `warnings` (предостережения EMA 4.4, необязательно), `side_effects`, `interactions` — string[]
- `sources` — ≥1

**Lookalike:** `herb` (ref → herbs, если двойник есть в базе) либо `name` + `latin`; `poisonous` (bool); `differences` (string, обяз.); `photo` (Photo, необяз.).

**SourceRef:** `{ id: ref → sources, page?: string }`.

### 5.2. Уровни доказанности

| Уровень | Значок | Значение | Допустимые типы источников |
|---|---|---|---|
| `proven` | зелёный | Подтверждено клиническими исследованиями; в т.ч. «well-established use» в монографиях EMA | `systematic_review`, `rct`, `article`, `monograph` |
| `traditional` | жёлтый | Признанное традиционное применение (EMA «traditional use», ВОЗ, фармакопея) без достаточных клинических данных | `monograph`, `pharmacopoeia`, `reference_book`, `book` |
| `folk` | оранжевый | Народная медицина, научно не проверялось | `book`, `reference_book` |
| `refuted` | красный | Исследования эффект не подтвердили | `systematic_review`, `rct`, `article` |

Сборщик проверяет: у показания уровня `proven` или `refuted` есть хотя бы один источник подходящего типа.

Порядок для сравнения и сортировки: `proven` > `traditional` > `folk` > `refuted`.

### 5.3. Источники (`content/sources.yaml`)

| Поле | Обяз. | Описание |
|---|---|---|
| `id` | да | Например `ema-matricariae-flos`, `amsterdam-2009` |
| `type` | да | `pharmacopoeia` \| `monograph` \| `systematic_review` \| `rct` \| `article` \| `book` \| `reference_book` |
| `title`, `authors[]`, `year` | да | |
| `publisher` / `journal` | нет | |
| `isbn` / `doi` / `pmid` / `url` | ≥1 | Без проверяемого идентификатора источник не принимается |
| `note` | нет | Комментарий |

Допустимые источники: фармакопеи (ГФ РФ, Европейская), монографии EMA HMPC и ВОЗ, систематические обзоры (в т.ч. Cochrane), рецензируемые статьи (PubMed), авторитетные справочники, книги пользователя. Недопустимые: блоги, форумы, сайты без автора и редакции, магазины.

### 5.4. Словари

| Словарь | Поля сверх `id` и `name` |
|---|---|
| indications | `organ_system` (ref → organ-systems), `synonyms[]` (для поиска) |
| organ-systems | — |
| substances | `class` (ref → substance-classes), `synonyms[]` |
| substance-classes | — (эфирные масла, флавоноиды, дубильные вещества…) |
| actions | `synonyms[]` |
| plant-parts | — (цветки, лист, трава, корень, кора, плоды, семена…) |
| habitats | — (лес, луг, болото, берег водоёма, обочина, огород…) |
| families | `latin` |

### 5.5. Фото

`file`, `kind` (`plant` целиком | `closeup` цветок/лист | `raw` сырьё), `caption?`, `author`, `license` (только `CC0`, `PD`, `CC BY *`, `CC BY-SA *`), `source_url` (страница файла на Wikimedia Commons).

Сжатие: WebP, по длинной стороне ≤ 1080 px, цель ≤ 150 КБ.

### 5.6. Сбор (`content/recipes/<id>.yaml`)

`id`, `name`, `purpose` (ref[] → indications), `components` (`[{ herb: ref, parts: number, part?: ref → plant-parts }]`, ≥2), `preparation`, `dosage`, `evidence` (как у Indication), `sources` (≥1), `safety_note` (необяз.).

### 5.7. Публикуемые файлы

`manifest.json`:

```json
{
  "schemaVersion": 1,
  "contentVersion": 202610151830,
  "publishedAt": "2026-10-15T18:30:00Z",
  "content": { "path": "content.json", "sha256": "…", "size": 812345 },
  "photos": [{ "path": "photos/<sha256>.webp", "sha256": "…", "size": 120345 }]
}
```

- `schemaVersion` — версия формата данных; увеличивается только при несовместимом изменении схемы.
- `contentVersion` — время сборки `YYYYMMDDHHmm` (монотонно растёт).
- `content.json` — все травы, сборы, словари и источники; ссылки на фото — пути вида `photos/<sha256>.webp`.

## 6. Приложение: экраны и поведение

### 6.1. Навигация

Нижние вкладки: **Травы** · **Каталог** · **Сборы** · **Избранное**. Настройки — иконка в шапке.

### 6.2. Экраны

1. **Травы (список).** Поиск, строка активных фильтров (чипы с ×), кнопка «+ фильтр», счётчик найденных, список: миниатюра, название, латынь, точка доказанности (если выбрано показание).
2. **Каталог.** Список группировок с количеством групп: от чего помогает · действующие вещества (и классы) · действие · система органов · «собирать сейчас» (текущий месяц) · часть растения · где растёт · семейство · жизненная форма (травы / кустарники / деревья…) · где взять (дикий / садовый / аптечный) · безопасность. Группировка → список групп → список трав (экран 1 с применённым фильтром).
3. **Карточка травы.** Галерея фото (с автором и лицензией под фото), название, латынь, семейство, звёздочка «в избранное», плашка «Черновик — не проверено» при `status: draft`. Разделы: от чего помогает (уровень, пояснение, раскрываемые источники) · действующие вещества · действие · сбор · применение · безопасность · с чем можно спутать (ядовитые — с красной рамкой) · мои заметки · источники. Все метки кликабельны и открывают список трав с этой меткой.
4. **Фильтры.** Группы чипов по всем группировкам + «доказанность не ниже». Кнопка «Показать N трав».
5. **Сборы.** Список сборов → карточка: состав (ссылки на травы с пропорциями), назначение, приготовление, дозировка, доказанность, источники.
6. **Избранное.** Травы со звёздочкой и травы с заметками.
7. **Настройки.** Версия и дата базы, «Проверить обновления», дисклеймер, список авторов фото и лицензий.

При первом запуске — однократный экран-дисклеймер: «Справочник носит информационный характер и не заменяет консультацию врача».

### 6.3. Логика фильтра

- Между разными группами — **И**.
- Внутри групп-признаков (показания, вещества, классы веществ, действия, системы органов, безопасность) — **И**: «и от кашля, и от бессонницы».
- Внутри групп-перечислений (месяц сбора, часть растения, место, семейство, жизненная форма, где взять) — **ИЛИ**: «июнь или июль».
- Месяц и часть растения проверяются **в одной записи `harvest`**: «цветки в июне» не совпадёт с травой, у которой в июне собирают корни.
- **Доказанность не ниже X:**
  - выбраны показания → каждое выбранное показание у травы должно иметь уровень ≥ X;
  - показания не выбраны → у травы есть хотя бы одно показание с уровнем ≥ X.
  - `refuted` всегда ниже любого порога.
- **Безопасность** (чипы): «можно при беременности» = `pregnancy: ok`; «можно при кормлении» = `lactation: ok`; «можно детям» = `children.status: ok`; «нетоксично» = `toxicity: none`.
- Выбор системы органов эквивалентен «хотя бы одно показание травы относится к этой системе».

### 6.4. Сортировка

- Выбраны показания → по наименьшему уровню доказанности среди выбранных показаний (по убыванию), затем по названию.
- Иначе → по русскому названию (с учётом «ё»).

### 6.5. Поиск

- Регистр не важен, «ё» = «е».
- Ищет подстроку в: названии, народных названиях, латинском названии.
- Отдельным блоком над результатами — совпавшие группы: показания, вещества, действия (по `name` и `synonyms`). Нажатие применяет фильтр.

### 6.6. Избранное и заметки

- Звёздочка в карточке и в списке (долгое нажатие).
- Заметка — свободный текст, сохраняется автоматически.
- Если трава исчезла из базы после обновления, а заметка осталась — в «Избранном» она показывается с пометкой «Трава удалена из базы» и текстом заметки.

## 7. Обновление базы

Проверка — при запуске и при возврате приложения на передний план, если с прошлой успешной проверки прошло ≥ 24 ч; либо вручную из настроек.

1. Загрузить `manifest.json` (таймаут 10 с). Нет сети / ошибка → выход, повтор при следующем запуске.
2. `schemaVersion` > поддерживаемой приложением → не применять; в настройках: «Доступна новая база, обновите приложение».
3. `contentVersion` ≤ текущей → выход.
4. Скачать `content.json` во временную папку, сверить sha256 и размер, распарсить и провалидировать схемой из `shared/`. Ошибка → удалить, выход.
5. Атомарно сделать новую базу активной (переименование файла), перезагрузить контент в памяти, показать уведомление «База обновлена: +N трав, изменено M».
6. Фото, которых нет ни во встроенных, ни в скачанных, догружаются в фоне по одному; ошибка отдельного фото не мешает остальному — вместо него заглушка, повтор при следующей проверке.
7. Скачанные фото, на которые больше не ссылается активная база, удаляются после успешного обновления.

Новая версия кода приложения (не базы) распространяется новым APK.

## 8. Подготовка контента

1. **Пилот: 10 трав.** Полностью заполненные карточки со всеми разделами. Пользователь проверяет формат и качество.
2. **Расширение до 40–50 трав** после одобрения пилота.
3. **Проверка источников.** Каждый источник проверяется в интернете при составлении (существует, совпадает название, авторы, год). Скрипт `tools/verify-sources` сверяет DOI через Crossref и PMID через PubMed (название должно совпадать); запускается вручную и в CI как предупреждение (не блокирует публикацию, т.к. внешние API бывают недоступны).
4. **Фото.** Скрипт `tools/fetch-photo` по имени файла на Wikimedia Commons скачивает изображение, берёт автора и лицензию из API, отклоняет недопустимые лицензии, сжимает в WebP и дописывает запись в `photos.yaml`.
5. **Книги пользователя.** Добавляются в `sources.yaml` (тип `book`/`reference_book`, ISBN); травы уточняются со ссылками на страницы.
6. Всё, что составил Claude, — `status: draft`. Перевод в `checked` — только пользователем.
7. **Страница проверки.** `npm run content:report` собирает `report/index.html` (не хранится в git): все травы и сборы с фото и авторством, названиями из словарей вместо id, цветными уровнями доказанности с пояснениями, кликабельными источниками и плашкой «черновик». По ней пользователь проверяет каждую партию.

## 9. Визуальный стиль

Направление: природный, спокойный, «здоровый», гармоничный. Финальная палитра, шрифты, формы и иллюстрации — по референсам, которые пришлёт пользователь.

До получения референсов: экраны реализуются на временной природной теме (зелёные и землистые тона, мягкие скругления, много воздуха). Цвета уровней доказанности остаются смысловыми (зелёный / жёлтый / оранжевый / красный), но подбираются в тон палитре. Вся стилистика — только через `theme/` (§4.3).

## 10. Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Нет сети | Работа на текущей базе, без сообщений |
| Битый/неполный `content.json` | Не применяется, текущая база остаётся |
| Несовместимый `schemaVersion` | Не применяется, подсказка обновить приложение |
| Нет фото | Заглушка |
| Ссылка в данных указывает в никуда (не должно случиться — ловит сборщик) | Элемент не показывается, ошибка пишется в лог |
| Не открылась внешняя ссылка источника | Системное сообщение «Не удалось открыть ссылку» |

## 11. Тестирование

- **Сборщик (`tools`)**: юнит-тесты на каждое правило валидации — несуществующая ссылка, показание без источника, `proven` без подходящего типа источника, источник без ISBN/DOI/PMID/URL, фото без лицензии, недопустимая лицензия, `id` не совпадает с именем файла, дубликаты `id`.
- **Логика приложения**: фильтры, сортировка, поиск — чистые функции, юнит-тесты (Jest) на тестовом наборе из ~8 вымышленных трав, включая правила И/ИЛИ, «месяц + часть в одной записи», порог доказанности, «ё».
- **Обновление**: тесты с подменой сети и файловой системы — новая версия, та же версия, битый sha256, невалидный JSON, несовместимый `schemaVersion`, офлайн, частичный провал фото.
- **CI**: на каждый push — тесты + сборка базы; публикация на GitHub Pages только из основной ветки и только при успешной валидации.
- **Интерфейс**: ручная проверка — Claude в веб-превью Expo, пользователь на телефоне через Expo Go; перед выпуском APK — на реальном устройстве.

## 12. Сборка и распространение

- APK собирается в облаке Expo (EAS Build, бесплатный тариф, профиль `preview` → `.apk`).
- Готовый APK выкладывается в GitHub Releases; близкие скачивают его по ссылке и ставят (разрешив установку из неизвестных источников).
- Обновления базы приходят сами (§7); обновления кода — новым APK.
