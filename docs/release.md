# Выпуск приложения «Травы»

Пошаговая инструкция для владельца репозитория. Всё выполняется из корня репозитория, если не сказано иное.

Адреса: репозиторий `NiyazAbuy/travi`, база по сети — `https://niyazabuy.github.io/travi/` (GitHub Pages).

## 1. Подготовить базу

1. Обновите встроенную базу: `npm run content:app`.
2. Проверьте всё: `npm run typecheck` и `npm test`.
3. Закоммитьте и отправьте в GitHub: `git add -A && git commit -m "..." && git push`.

### Как выпускается новая база

Версия базы (`contentVersion`) — это время (UTC, `ГГГГММДДччмм`) **последнего коммита, который менял что-либо в `content/`**. Одинаковое содержимое даёт одинаковую версию и на вашем компьютере, и в CI, поэтому свежесобранный APK не скачивает ту же самую базу повторно.

Следствие: если вы изменили только код сборщика (например, сжатие фото), но не трогали `content/`, новая версия базы **не выйдет**. Чтобы выпустить её, нужна любая правка в `content/` (даже пробел в тексте). Если в `content/` есть незакоммиченные изменения или git недоступен, берётся текущее время (так работает разработка).

## 2. Собрать APK

Первый раз:

1. Заведите аккаунт на [expo.dev](https://expo.dev).
2. Войдите: `npx eas-cli login` (это делаете вы сами).
3. Привяжите проект: `cd app && npx eas-cli init`.

Сама сборка (профиль `preview` собирает APK для установки напрямую):

```
cd app
npx eas-cli build -p android --profile preview
```

При первой сборке EAS предложит создать ключ подписи — соглашайтесь. Сборка идёт в облаке Expo; в конце в выводе будет ссылка на `.apk`.

## 3. Опубликовать релиз на GitHub

1. Скачайте `.apk` по ссылке из вывода EAS и переименуйте в `travy-<version>.apk` (например, `travy-1.0.0.apk`).
2. GitHub → репозиторий `NiyazAbuy/travi` → Releases → «Draft a new release».
3. Тег `v<version>` (например, `v1.0.0`), приложите APK, нажмите «Publish release».
4. Поставьте APK на свой телефон и проверьте до раздачи близким.

## 4. Перед следующим выпуском

В `app/app.json` увеличьте `version` (например, `1.0.0` → `1.0.1`) и `android.versionCode` (на единицу: `1` → `2`). Без этого новый APK не встанет поверх старого. Затем повторите шаги 1–3.

## 5. Резервная копия ключа подписи

Ключ подписи хранит Expo. Если потерять доступ к аккаунту Expo, новые версии не встанут поверх установленных старых. Сделайте копию заранее:

1. `cd app && npx eas-cli credentials -p android`
2. Выберите окружение сборки (`preview`), затем управление ключом (Keystore) и пункт «Download credentials».
3. Сохраните скачанный файл и пароли в надёжном месте (не в репозитории).

Названия пунктов меню в EAS могут чуть отличаться между версиями CLI — ищите пункт со словами «Download» и «credentials»/«keystore».
