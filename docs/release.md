# Выпуск приложения «Травы»

Пошаговая инструкция для владельца репозитория. Всё выполняется из корня репозитория, если не сказано иное.

Адреса: репозиторий `NiyazAbuy/travi`, база по сети — `https://niyazabuy.github.io/travi/` (GitHub Pages).

## 1. Подготовить базу

Порядок важен: Pages публикует базу только из ветки `main`, а EAS собирает только закоммиченный код.

1. Если вы правили `content/`, закоммитьте эти правки первыми, например:

   ```
   git add content
   git commit -m "content: добавлена ромашка"
   ```

2. Обновите встроенную базу:

   ```
   npm run content:app
   ```

3. Проверьте всё (команды выполняйте по одной):

   ```
   npm run typecheck
   npm test
   ```

4. Закоммитьте изменения встроенной базы и отправьте в `main`:

   ```
   git add -A
   git commit -m "build: обновлена встроенная база"
   git push origin main
   ```

5. Дождитесь зелёного CI (https://github.com/NiyazAbuy/travi/actions) и новой базы на Pages: на `https://niyazabuy.github.io/travi/manifest.json` должен появиться новый `contentVersion`.

> Все команды в этой инструкции выполняйте по одной строке из корня репозитория (блоки с `cd app` заканчиваются `cd ..`): в Windows PowerShell 5.1 цепочки через `&&` не работают.

### Как выпускается новая база

Версия базы (`contentVersion`) — это время (UTC, `ГГГГММДДччмм`) **последнего коммита, который менял что-либо в `content/`**. Одинаковое содержимое даёт одинаковую версию и на вашем компьютере, и в CI, поэтому свежесобранный APK не скачивает ту же самую базу повторно.

Следствие: если вы изменили только код сборщика (например, сжатие фото), но не трогали `content/`, новая версия базы **не выйдет**. Чтобы выпустить её, нужна любая правка в `content/` (даже пробел в тексте). Если в `content/` есть незакоммиченные изменения или git недоступен, берётся текущее время (так работает разработка).

Два коммита в `content/`, отправленные в пределах одной минуты (UTC), получают одну и ту же версию базы: телефоны оставят первую из них до следующего изменения `content/`. Между такими отправками выжидайте минуту.

## 2. Собрать APK

Первый раз:

1. Заведите аккаунт на [expo.dev](https://expo.dev).
2. Войдите: `npx eas-cli login` (это делаете вы сами).
3. Привяжите проект:

   ```
   cd app
   npx eas-cli init
   cd ..
   ```

4. EAS допишет `projectId` в `app/app.json`. Закоммитьте этот файл и отправьте в `main`:

   ```
   git add app/app.json
   git commit -m "build(app): EAS projectId"
   git push origin main
   ```

Сама сборка (профиль `preview` собирает APK для установки напрямую):

```
cd app
npx eas-cli build -p android --profile preview
cd ..
```

При первой сборке EAS предложит создать ключ подписи — соглашайтесь. Сборка идёт в облаке Expo; в конце в выводе будет ссылка на `.apk`.

## 3. Проверить APK на телефоне и опубликовать релиз

1. Скачайте `.apk` по ссылке из вывода EAS и переименуйте в `travy-<version>.apk` (например, `travy-1.0.0.apk`).
2. Поставьте APK на свой телефон и проверьте: запуск без сети, карточка травы, фото, избранное, заметка.

### Первый выпуск: проверить обновление базы на телефоне

Сделайте это до публикации релиза. Здесь проверяется самое важное — что телефон правда скачивает новую базу из сети.

1. Внесите небольшую настоящую правку в `content/` (лучше заменить или добавить одно фото).
2. Закоммитьте и отправьте в `main`:

   ```
   git add content
   git commit -m "content: проверка обновления на телефоне"
   git push origin main
   ```

3. Дождитесь, пока на `https://niyazabuy.github.io/travi/manifest.json` не появится новый `contentVersion`.
4. На телефоне откройте «О приложении» и нажмите «Проверить обновления». Ожидается «База обновлена: изменено 1» (или похожее), источник базы — «Скачана из сети», а через некоторое время появляется новое фото.
5. Закройте приложение, выключите на телефоне интернет и откройте его снова: скачанная база должна остаться.

Только после этого публикуйте релиз.

### Публикация релиза

1. GitHub → репозиторий `NiyazAbuy/travi` → Releases → «Draft a new release».
2. Тег `v<version>` (например, `v1.0.0`), приложите APK, нажмите «Publish release».

## 4. Перед следующим выпуском

В `app/app.json` увеличьте `version` (например, `1.0.0` → `1.0.1`) и `android.versionCode` (на единицу: `1` → `2`). Без этого новый APK не встанет поверх старого. Затем повторите шаги 1–3.

## 5. Резервная копия ключа подписи

Ключ подписи хранит Expo. Если потерять доступ к аккаунту Expo, новые версии не встанут поверх установленных старых. Сделайте копию заранее:

1. Запустите:

   ```
   cd app
   npx eas-cli credentials -p android
   cd ..
   ```
2. Выберите окружение сборки (`preview`), затем управление ключом (Keystore) и пункт «Download credentials».
3. Сохраните скачанный файл и пароли в надёжном месте (не в репозитории).

Названия пунктов меню в EAS могут чуть отличаться между версиями CLI — ищите пункт со словами «Download» и «credentials»/«keystore».
